# ai-merchant-revenue-agent
AI-powered merchant revenue agent for agentic commerce using Razorpay
AI Merchant Revenue Agent
AI-powered conversational commerce system that helps merchants increase revenue through intelligent product discovery, contextual cross-selling, and secure payment processing.
---
Overview
Traditional e-commerce requires customers to search through product catalogs manually.
The AI Merchant Revenue Agent provides a conversational shopping experience where customers can describe what they need in natural language.
For example:
> I need something for coding under ₹1000
The system understands the customer's intent, recommends a suitable product from the merchant catalog, identifies a relevant cross-sell opportunity, calculates the resulting basket value, and enables the customer to complete the purchase through Razorpay Test Mode.
The system separates AI decision-making from financial operations:
The AI understands customer intent and recommends products.
The deterministic backend validates products, stock, pricing, cart totals, orders, and payments.
This creates a controlled and auditable commerce workflow.
---
Problem
Merchants face two important challenges:
Customers often need to search through large product catalogs before finding what they want.
Relevant cross-sell opportunities are often missed, reducing potential basket value.
The goal of this project is to make product discovery conversational while helping merchants increase revenue through contextual recommendations.
---
Solution
The AI Merchant Revenue Agent creates an end-to-end conversational commerce workflow:
```text
Customer Request
       ↓
AI Intent Understanding
       ↓
Product Search
       ↓
Catalog & Stock Validation
       ↓
AI Product Recommendation
       ↓
Contextual Cross-sell
       ↓
Customer Approval
       ↓
Server-side Cart Validation
       ↓
Razorpay Checkout
       ↓
Server-side Payment Verification
       ↓
PostgreSQL Persistence
       ↓
Audit Trail + Merchant Dashboard
```

Key Features
1. Natural Language Product Discovery
Customers can describe their requirements naturally.
Example:
```text
I need something for coding under ₹1000
```
The AI extracts relevant intent such as product category and budget and uses it to identify suitable catalog products.
---
2. Catalog-backed AI Recommendations
Recommendations are grounded in the merchant's product catalog.
The backend validates:
Product ID
Product availability
Stock
Price
Budget constraints
The AI cannot invent arbitrary products or prices.
---
3. Contextual Cross-selling
The system identifies products that are configured as related products in the merchant catalog.
For example:
```text
Base Product:
TechPro Wireless Mouse
₹799

AI Cross-sell:
Premium Headphone Stand
₹499
```
The customer explicitly chooses whether to add the cross-sell.
---
4. Revenue Impact Measurement
The application calculates the additional basket value generated by the AI cross-sell.
Example:
```text
Original purchase: ₹799
AI cross-sell:      ₹499
Updated basket:     ₹1,298
Basket increase:    +62.5%
```
This makes the revenue impact of contextual recommendations visible.
---
5. Secure Cart Calculation
The frontend sends product IDs and quantities to the backend.
The backend reconstructs the cart using the trusted merchant catalog and calculates the actual price.
This prevents the frontend from controlling the final payment amount.
---
6. Razorpay Test Mode Checkout
The application integrates Razorpay Test Mode for the checkout flow.
```text
Create Local Order
       ↓
Create Razorpay Order
       ↓
Open Razorpay Checkout
       ↓
Customer Authorizes Payment
       ↓
Razorpay Returns Payment Details
       ↓
Server-side Verification
       ↓
Order Marked PAID
```
---
7. Server-side Payment Verification
The backend verifies payment information before marking an order as paid.
The browser response alone is not trusted for determining payment success.
---
8. PostgreSQL Persistence
The following transaction data is stored in PostgreSQL:
```text
Orders
Order Items
Payments
Audit Logs
```
This provides persistent transaction state and allows the merchant dashboard to display real stored data.
---
9. Audit Trail
Important application actions are recorded as audit events.
Examples:
```text
INTENT_PARSED
PRODUCT_RECOMMENDED
ORDER_CREATED
PAYMENT_CREATED
PAYMENT_VERIFIED
ORDER_PAID
PAYMENT_FAILED
```
This makes the transaction flow traceable and easier to debug or review.
---
10. Graceful Payment Failure and Retry
The application handles failed or cancelled payments without falsely marking the order as successful.
Example:
```text
Payment Not Completed

Your order is still pending.
You can try the payment again.

[ Retry Payment ]
```
The customer can retry the payment from the same cart.
---
11. Merchant Dashboard
The merchant dashboard provides visibility into:
Total orders
Paid orders
Total revenue
Verified payments
Recent orders
Recent agent activity
Audit events
---
Security Design
AI-assisted, not AI-controlled
A central design principle is:
> **The LLM does not control money movement.**
The AI is responsible for:
```text
Intent Understanding
Product Recommendation
Recommendation Reasoning
```
The deterministic backend is responsible for:
```text
Product Validation
Stock Validation
Price Calculation
Cart Calculation
Order Creation
Payment Creation
Payment Verification
Database Persistence
Audit Logging
```
Example
Customer:
```text
I need something for coding under ₹1000
```
The AI may identify:
```text
Category: Accessories
Budget: ₹1000
```
The backend then determines which actual products satisfy those constraints.
The final payment amount is calculated from the trusted catalog rather than accepted directly from the browser.

Running Locally
1. Clone the repository
```bash
git clone https://github.com/Likhitha3090/ai-merchant-revenue-agent.git
```
2. Enter the project
```bash
cd ai-merchant-revenue-agent
```
3. Create a virtual environment
```bash
python -m venv venv
```
4. Activate the environment
Windows PowerShell:
```powershell
.\venv\Scripts\Activate.ps1
```
5. Install dependencies
```bash
pip install -r requirements.txt
```
6. Configure environment variables
Create a `.env` file in the project root.
Example:
```env
GROQ_API_KEY=your_groq_api_key

RAZORPAY_KEY_ID=your_razorpay_test_key_id
RAZORPAY_KEY_SECRET=your_razorpay_test_key_secret

DB_USER=postgres
DB_PASSWORD=your_postgres_password
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=ai_merchant_db
```
Do not commit `.env` to GitHub.

Failure Recovery
The project includes a graceful payment failure and retry path:
```text
Customer starts payment
        ↓
Razorpay Checkout
        ↓
Payment cancelled / failed
        ↓
Order remains pending
        ↓
Retry Payment displayed
        ↓
Customer retries
        ↓
New payment attempt
```
This prevents customers from being stuck after a failed checkout attempt.
A detailed account of a real development failure and how it was diagnosed and resolved is included separately in `WHAT_BROKE.md`, as required for the Razorpay AI Buildathon submission.

Design Principles
1. AI-assisted commerce
AI is used where language understanding and recommendation reasoning are valuable.
2. Deterministic financial operations
Pricing, stock, order totals, and payment verification remain under backend control.
3. Customer authorization
Cross-sell products require explicit customer approval.
4. Explainability
Important system actions are recorded through an audit trail.
5. Graceful failure
Failed or cancelled payments do not silently become successful transactions.
6. Bounded financial actions
The system does not allow the LLM or browser to directly determine the final payment amount.
